# 更新のやり方

年に2〜3回、これをなぞるだけで終わります。所要10分程度。

---

## 手順1　取ってくる

```bash
python3 tools/check.py 110 --year 2027
```

`110` は次の回数、`--year` は年が省略されている日付に補う年です。

- 各ページの生存確認（404なら未公開）
- ISO-2022-JP を UTF-8 に変換
- 日付らしい箇所を前後の文脈つきで抽出
- 本文を `tools/out/` に保存

## 手順2　Claude Code に読ませる

以下をそのまま貼ります。

```
tools/out/ 以下のテキストと C110_report.json を読んで、circle-ops/index.html の DATA を
更新する差分を作ってください。

【やること】
1. deadlines の各項目を、抽出された日付で更新する
   - name / at / note / src を埋める
   - src には、その日付が書かれていたページのURLを入れる
2. after.items のうち、日程が確定したものは at: null を実際の日時に変える
   - まだ発表されていないものは at: null のままにする
3. after.items の pdf.url が空のもので、今回公開されているPDFがあれば入れる
4. event の name / dates / venue / fee を今回のものに更新する
5. links のうち、URLに回数が入っているものを差し替える
6. updated を今日の日付にする

【守ること】
- 日時は必ず "+09:00" を付ける
- 時刻が書かれていない締切（消印有効など）は 23:59:59 にする
- 抽出結果に迷いがあるものは、勝手に決めずに「確認が必要」として一覧に出す
- 年が補完された日付（year_guessed: true）や月を引き継いだ日付（month_inherited: true）は必ず報告する
- DATA に項目を足すときは、必ず既存の項目をコピーして書き換えること（ゼロから書き起こすとフィールドの欠落で表示が欠ける原因になります）
- DATA の外は書き換えない

【最後に】
更新した項目を「項目名 / 変わった日時 / 出典URL」の表で出してください。
公式ページを開いて突き合わせます。
```

## 手順3　突き合わせる

Claude Codeが出した表と、公式ページを見比べます。**ここは省略しないでください。**
このスクリプトは日付を「拾う」だけで、それが何の締切かの判断はしていません。

確認できたら commit して終わりです。

---

## 抽出結果の見方

`--year` で補完した日付には `※年を補完`、直前の月から引き継いだ日付には `※月を引き継ぎ`（`month_inherited`）が付きます。
年をまたぐ冬開催（12月開催で申請が11月）では補完した年が1年ずれることがあるため、`month_inherited` や `year_guessed` の印が付いた候補は必ず公式ページで確認してください。

日付の前後45文字にキーワードが無いものは捨てているので、逆に近くに関係ない日付が
あると巻き込まれます。「2005年12月10日」のようなページ更新履歴の日付が混ざったら
無視してください。ノイズは取りこぼしよりましという方針にしています。

## 404が返ったとき・抽出されない形式

2つの可能性があります。

1. **まだ公開されていない** — 搬入・搬出の手引きは当落発表後に出ます
2. **URLの規則から外れた** — 大文字小文字の揺れが過去にありました

判別するには、申込サークルサポートページを開いて、そこからリンクを辿ります。
規則が変わっていたら `tools/check.py` の `PER_EVENT` を直してください。

なお、スラッシュ形式の日付（`8/19` や `2026/8/19` など）は誤検出を避けるため抽出しない仕様です。公式の記載がスラッシュ形式の場合は手動で確認してください。

## コミケットアピールについて

アピールのURLは当落速報メールと通行証裏のQRでしか案内されないため、このスクリプト
では取得できません。駐車券など、アピールにしか載っていない情報は手で入れます。
